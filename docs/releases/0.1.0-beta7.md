# PXE Tools 0.1.0 bêta 7 — candidate, non publiée

Cette candidate traite l’issue #56 : le cycle normal de mise à niveau APT ne doit plus demander l’arrêt manuel des services lorsqu’ils sont au repos. Le numéro prépare des octets identifiables pour la réception depuis les versions publiques bêta 5 et bêta 6 ; il ne crée ni tag GitHub ni publication APT. Le manifeste de production reste en bêta 6.

## Changement prévu

Le paquet capture l’état des services et leur politique de démarrage, établit une barrière de quiescence, arrête les unités concernées et conserve un snapshot local privé de l’instance avant remplacement/migrations. Une configuration réussie reprend uniquement les rôles antérieurement actifs. Les comptes, données, réglages, clés et l’onboarding existants sont préservés ; aucun PXE/proxy désactivé n’est activé automatiquement.

L’APT standard et non interactif est le parcours visé. Aucun réglage unattended-upgrades global, nouveau daemon, secret, droit ou infrastructure n’est ajouté. Un vrai travail en cours ou une configuration dont l’autorité ne peut être établie reste un refus explicite, avec reprise ciblée après correction. Une file technique simplement pending ne suffit pas à bloquer la mise à niveau.

## Erreurs et reprise

La préparation avant dépaquetage peut compenser un échec avec les anciens programmes lorsque leur intégrité opérationnelle est encore garantie. Après dépaquetage ou migration, aucun rollback de DB ni démarrage de fichiers potentiellement mélangés n’est simulé. Le journal initial et le snapshot sont conservés pour une reprise idempotente. Une reprise de configure utilise l’intention initiale, pas l’état temporairement arrêté.

Voir [le protocole et les limites](../apt-upgrade-lifecycle.md). Le snapshot local ne remplace pas une sauvegarde complète distante ; les médias HTTP/TFTP et ISO restent en place et ne sont pas dupliqués à chaque mise à niveau.

## Validation technique reçue, diffusion encore distincte

Les 33 tests du cycle SQLite/fichiers avec systemd simulé et la revue indépendante sont reçus. Sur Zorin 18.1, les vraies transactions APT non interactives bêta 5 et bêta 6 → candidat 7 ont réussi dans les quatre états proxy actif, DHCP externe actif, console seule et services arrêtés/target enabled. Un vrai travail concurrent est refusé sans interruption et un configure échoué reprend avec la même sauvegarde après correction. Les données, comptes, clés, paramètres, médias et politiques de démarrage sont conservés.

Des transactions et réinstallations APT ont également réussi sur Debian 12/systemd 252 et Ubuntu 26/systemd 259 avec administration active et réseau arrêté. Debian 13 est couvert par la CI, pas une nouvelle transaction systemd réelle ; Ubuntu 24.04 direct n’a pas été reçu séparément de la base noble de Zorin. Voir [la portée détaillée](../apt-upgrade-lifecycle.md).

Ces résultats initiaux portent sur le code `ce09d2ca` et les artefacts de laboratoire. Le développement ne dépend pas de cette attente. Aucune nouvelle release n’est autorisée par cette préparation seule.
