# PXE Tools 0.1.0 bêta 10

La bêta 10 rassemble les corrections natives préparées après la bêta 8 et
les améliorations de la console. Elle est numérotée au-dessus des candidats
locaux bêta 9 afin de permettre leur mise à niveau par APT.

## Installation et désinstallation

- La première installation native ne dépend plus des permissions de groupe de
  `/var/log` : les journaux propres à PXE Tools sont placés dans son runtime protégé.
- Une configuration initiale interrompue peut reprendre lorsque son journal et
  les preuves de création sont suffisants ; les cas ambigus restent préservés.
- Le désinstallateur traite les installations anciennes ou incomplètes lorsque
  les preuves applicables sont suffisantes et conserve les ressources non attestées.
- Les caches Python reconnus sont nettoyés en sécurité avant la purge ; les
  fichiers inconnus restent préservés.

## Console

- Le thème clair reprend la palette et la typographie du site. Les préférences
  d'apparence clair, sombre et système restent disponibles.
- Une vue d'ensemble présente la configuration réseau, les images lisibles,
  l'activité et le diagnostic HTTP PXE. Un état non observé reste indiqué comme tel.
- L'appellation des équipements est réglable pour toute l'instance : Machine
  par défaut, Client PXE, Ordinateur ou Serveur. Les noms d'hôte et les données
  conservées ne sont pas modifiés.

## Portée et validation

Le paquet `pxe-tools` fournit le socle natif. Le module `pxe-tools-ansible`
reste facultatif. L'administration démarre lors d'une première installation ;
les services de démarrage PXE sont activés après configuration explicite.

Les correctifs ont été vérifiés par les tests applicatifs et APT en CI, ainsi
que par des essais ciblés de reprise et de purge. Des candidats locaux plus
anciens intégrant la console et ses réglages ont été installés sur PC-Dell sous
Zorin OS. La bêta 10 produite par la CI doit encore faire l'objet d'un cycle
réel complet de désinstallation et de réinstallation sur ce matériel ; un
transfert TFTP vérifié ne constitue pas une validation de démarrage PXE physique.

Les identifiants du build, les empreintes et l'état de publication sont établis
par le manifeste de publication et la préversion GitHub correspondante.
